# Архитектура

Краткое описание ключевых решений и компромиссов.

---

## FSD

Код разделeн на слои, каждый слой импортирует только слои ниже себя:

```
app → views → widgets → features → entities → shared
```

| Слой       | Что лежит                    | Примеры                                      |
| ---------- | ---------------------------- | -------------------------------------------- |
| `app`      | маршруты Next.js, провайдеры | `_providers/app.providers.tsx`, `layout.tsx` |
| `views`    | страницы                     | страница доски, профиль                      |
| `widgets`  | крупные блоки экрана         | шапка, список досок, канбан                  |
| `features` | действия пользователя        | вход, создание задачи, фильтры, смена темы   |
| `entities` | сущности предметной области  | пользователь, доска, задача                  |
| `shared`   | код без бизнес-логики        | UI-кит, API-клиент, стили                    |

Максимально пытался придерживаться документации, и избегать кастомок, но папку pages в nextjs не рекомендуется делать, так как nextjs воспринимает как Pages Router, в целях избежать конфликтов `pages` был сменен на `views`.

Внутри слайса код разделeн на сегменты по назначению: `ui` — отображение, `model` — состояние и логика, `api` — работа с сервером, `lib` — чистые функции, `config` — константы.

**Публичный API.** Снаружи слайса импортируется только его `index.ts`. Внутреннюю структуру слайса можно менять, не трогая остальной код.

**Личные решения**

- файлы и папки в kebab-case;
- файлы с общими именами получают префикс слайса и роль: `task.types.ts`, `auth.schema.ts`, `board.api.ts`,;
- хуки слайсов — `<слайс>-<имя>.hook.ts`, переиспользуемые хуки из `shared` - `use*.ts`.

## API-слой

- **Один экземпляр Axios** в `shared/api`. Request-интерсептор подставляет токен, response-интерсептор приводит любую ошибку к единому типу `ApiError` и обрабатывает `401`.
- **Инверсия зависимостей.** Axios живeт в `shared`, а токен — в `entities/user`, и нижний слой не может импортировать верхний. Поэтому `shared` предоставляет функцию `configureApi`, а источник токена подключается в слое `app`.
- **Типизированные ошибки.** `ApiError` зарегистрирован в TanStack Query как тип ошибки по умолчанию, поэтому `error` в любом хуке типизирован без приведений.
- **Пути API** описаны один раз в `API_ENDPOINTS` и используются и запросами, и мок-хендлерами, так же ключи для TanStack Query описаны в `QUERY_KEYS`.

## Авторизация

- Токен и пользователь хранятся в Zustand с сохранением в localStorage, сессия переживает перезагрузку.
- Маршруты защищены на клиенте: `ProtectedRoute` для авторизованной части, `GuestRoute` для страниц входа и регистрации.
- Пока сессия не прочитана из localStorage, гарды показывают загрузку. Это исключает расхождение между серверным и клиентским рендером и мигание формы входа. Состояние гидрации читается через `useSyncExternalStore`.
- При `401` от любого запроса интерсептор очищает сессию, а гард перенаправляет на вход.
  **Компромисс:** с настоящим бэкендом токен стоило бы хранить в httpOnly cookie защита от XSS, но все приложение живет в браузере так что нет толку.

## Канбан

- Колонки строятся на клиенте: сервер отдаeт плоский список задач, `groupTasksByStatus` раскладывает его по статусу.
- Перетаскивание сделано на `@dnd-kit/core`. Карточка — `useDraggable`, колонка — `useDroppable` с `id`, равным статусу, поэтому в `onDragEnd` `over.id` — это сразу новый статус задачи.
- Отдельные сенсоры для мыши - старт после сдвига на 5 px, чтобы работал клик, и касания - старт после удержания, чтобы работала прокрутка.
- **Оптимистичное обновление** смены статуса: кэш меняется до ответа сервера, при ошибке откатывается, после — сверяется с сервером. Без этого карточка после броска на долю секунды возвращалась в старую колонку.
- `DragOverlay` рисует копию карточки поверх страницы, анимация возврата отключена, потому что она летела в старую позицию карточки.

## Профиль

Аватар загружается файлом и хранится как data URL. Размер ограничен 300 КБ, потому что данные лежат в localStorage с лимитом около 5 МБ на сайт.

## Тема и стили

- Компоненты используют только CSS-переменные, темная тема переопределяет их под `[data-theme='dark']`, поэтому смена темы не требует изменений в компонентах.
- Выбор темы хранится в localStorage.
- Inline-скрипт в `<head>` ставит тему до отрисовки страницы, ещe до загрузки React, и исключает вспышку светлой темы.
